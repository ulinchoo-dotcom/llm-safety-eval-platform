# 大模型安全评测平台项目启动与验收清单

依据《大模型安全评测平台_交接文档》v1.0 整理。经用户授权参考 dify-eval 新建独立仓库；已落地用例管理、模拟评测和人工复核后端。本文区分目标验收要求与实际开发进度；最新能力与限制以 README 为准。

## 第一阶段交付边界

按 M1 → M4 推进。首先核对已有架构、运行方式、数据库迁移、测试和未提交改动，再补齐分类体系与用例管理底座。保留仓库现有规范，不在未知代码基础上替换架构。

第一批代码优先实现：

1. 将 5 大类、23 子类和 8 类攻击手法作为版本化配置，并校验子类和大类的归属关系。
2. 建立用例数据模型和迁移，支持多轮输入、正常对照样本、来源、父用例、验证状态和手册版本。
3. 提供用例导入、查询及覆盖统计；导入时校验必填字段、枚举、重复编号和标签组合，错误应定位到记录。
4. 建立判定手册四段式骨架与标注规则；所有生成或变异样本默认未经验证，只有独立标注与仲裁流程能够确认标签。
5. 为标签约束、导入事务、覆盖率统计及一致性计算补充测试。

本批完成后仍须人工完成手册评审和种子样本验证，不能据此宣称 M1 验收通过。

## 实施前需要补齐的数据口径

以下为工程补充建议，不是交接文档已经给出的事实或现有系统能力。

### 正常对照样本与攻击样本必须区分

误伤率需要正常样本作为分母。建议增加 `case_kind`，区分 `adversarial` 与 `benign_control`；正常样本允许攻击手法为空。5 × 8 的覆盖矩阵仅统计攻击样本，不能用正常样本填充攻击覆盖。

### 输入标签不等于输出判定

用例的风险标签、期望严重程度和期望行为，应与模型输出的实际标签、严重程度、是否拒答及是否通过分别保存。仅提及敏感主题、进行教育说明或保护性求助，不应自动被算作攻击成功。每一子类需列出允许内容与不允许内容的边界，并由项目负责人确认。

### 未知结果不得视为通过

调用异常、Judge 无效输出、待人工复核和已经裁定的样本应区分。调用异常不计入安全判定，但报告必须同时展示计划数、成功调用数、已裁定数、异常数和待复核数。安全比率展示分子与分母；分母为零时为不可计算，不能用 0% 代替。未裁定样本不计入最终安全比率，不能让不完整报告自动通过发布门禁。

### Kappa 必须指定比较字段

分别计算风险子类、严重等级与处置策略的一致性，并保留混淆矩阵。综合标签的拼接方式若用于门禁，应作为明确配置固定下来。空双标集或随机一致率为 1 时，Kappa 不可计算，不能当作满分。交接文档未明确哪个字段的 Kappa 用于 0.85 门槛，需要在 M1 验收前确定。

### Judge 准入需绑定版本

校准结论绑定 Judge 模型、Prompt、手册版本与校准集快照；缺少任一大类、样本不足或单类不达标时不准入。提示词调试集与最终验收集应分开，避免在同一数据上反复调整后高估一致率。交接文档未定义一致率比较字段，需明确是通过结论、风险标签或组合判定。

### 预算阈值与降速是两个约束

降速只能限制支出速度，不能保证总费用不超限。建议分别设置调用速率与本轮总预算；预算耗尽时暂停新请求、保留进度并等待增加预算或缩减任务。与原文“超预算自动降速”之间的差异，应在启用真实 API 前确认。

### 版本快照确保结果可复现

评测开始时冻结用例集、模型标识、系统 Prompt、手册和 Judge Prompt。原始输入输出、调用角色（被测模型或 Judge）、耗时、输入和输出 Token、币种、价格版本与费用应逐次记录，失败与重试也要留痕。API 不提供用量时标记缺失或估算，不得写入伪造的零值。

## 测试优先级

- 数据校验：大类与子类不匹配、未知枚举、重复用例、多轮消息格式和无来源样本。
- 导入：整批事务回滚、重复导入策略、错误定位、待验证状态不可被普通导入绕过。
- 统计：正常样本不进入攻击分母，异常与待复核结果不冒充通过，零分母和单标签 Kappa 正确处理。
- 后续标注台：两人不可查看对方结果、同人不能重复双标、第三人仲裁、仲裁回写保留历史。
- 后续 Pipeline：重试与独立限速、模型适配层、调用审计、低置信转人工、版本校准失效和回归阻断。
